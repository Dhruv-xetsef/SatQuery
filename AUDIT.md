# SatQuery AI — Technical Audit Report (`AUDIT.md`)

This document provides a systematic audit of the SatQuery AI repository (`satquery2.0`) against **ISRO Problem Statement 26167** and technical requirements.

---

| Requirement | Current implementation | File | Status | Required change |
|---|---|---|---|---|
| **1. Single-Image Remote-Sensing VQA** | Keyword matching rules (`if "water" in query: ...`) returning hardcoded templates and clamped confidence values. | `backend/models/vqa_caption_tool.py`, `backend/models/rs_adapter.py` | PARTIAL | Replace template/keyword logic with a real vision-language/VQA inference pipeline conditioned on visual features & natural language question. |
| **2. Single-Image Text-Guided Grounding** | Predetermined bounding boxes (e.g. `ymin=0.10*h`) and synthetic text overlays with hardcoded "IoU 0.91" text. | `backend/models/grounding_tool.py` | FAIL | Implement genuine text-guided spatial grounding and contour/mask delineation based on visual features and target text phrase. |
| **3. Bi-Temporal Change Analysis & Change VQA** | Calculates image diff, but uses hardcoded text templates ("South-Eastern quadrant", "Built-Up HAS INCREASED"), fixed confidence `0.945`, and duplicates single images if 2nd image is missing. | `backend/models/change_vqa_tool.py`, `backend/registry.py`, `backend/agent_planner.py` | PARTIAL | Implement genuine bi-temporal feature extraction, diffing, real change quantification, and change-VQA. Reject single-image inputs with clear error. |
| **4. Co-Registered Optical + SAR Cross-Modal Analysis** | Basic brightness thresholding heuristic with fixed text outputs, hardcoded `0.962` confidence, and synthetic SAR generation if SAR input is missing. | `backend/models/optical_sar_tool.py`, `backend/registry.py`, `backend/agent_planner.py` | PARTIAL | Implement genuine optical+SAR multimodal feature fusion. Enforce strict dual-modality validation and reject single or non-matching inputs. |
| **5. Remote-Sensing Model Adaptation / Fine-tuning** | `training/` directory has no python scripts or training code. `rs_adapter.py` is an un-trained ResNet-18 skeleton without training pipeline. | `training/`, `backend/models/rs_adapter.py` | NOT IMPLEMENTED | Implement genuine training and evaluation scripts (`training/train_remote_sensing.py`, `training/evaluate_remote_sensing.py`, dataset loaders, configs, checkpoint saving). |
| **6. Agentic Task Routing & Specialist Model Orchestration** | Keyword-based intent routing with fallback duplicate-image behavior when inputs do not match requirements. | `backend/query_engine.py`, `backend/agent_planner.py`, `backend/registry.py` | PARTIAL | Implement explicit structured query parsing (`QueryUnderstandingEngine`) and input-compatibility routing without fallback image fabrication. |
| **7. Evidence-Grounded Answers & Visual Overlays** | Overlays generated with hardcoded bounding box coordinates or fake IoU numbers. | `backend/evidence_generator.py`, `backend/models/*.py` | PARTIAL | Ground all visual evidence artifacts (bounding box, segmentation mask, change map, optical-SAR composite) strictly on calculated visual predictions. |
| **8. Calibrated Confidence & Trust Evaluation** | Hardcoded tool confidences (`0.925`, `0.962`, `0.945`, clamped `0.86-0.96`). Trust engine uses hardcoded `94.5` and `96.0` percentages. | `backend/trust_uncertainty.py`, `backend/models/*.py` | FAIL | Derive confidence directly from model probabilities/logits, segmentation variance, or feature agreement. Explicitly label heuristic fallbacks. |
| **9. Observable Execution Trace** | Basic trace structure logging pipeline steps and execution timing. | `backend/audit_trace.py`, `backend/agent.py` | PASS | Preserve and refine audit trace to record structured query intent, verified inputs, executed tools, parameters, and evidence outputs. |
| **10. Benchmark Evaluation Suite** | Synthetic test script (`eval_benchmarks.py`) computing arbitrary scores `(conf * 50) + (rel_score * 0.5)` without ground truth comparison. Claims fake 93.16 score. | `eval_benchmarks.py`, `README.md` | FAIL | Rebuild evaluation suite under `evaluation/` with standard metrics (VQA accuracy, IoU, Dice/F1) using real ground truth data. Remove fake scores from README. |
| **11. GeoTIFF / TIFF Input Validation** | Uses rasterio for basic channel reading, but auto-fabricates missing images and ignores spatial alignment, CRS, and dimension mismatch errors. | `backend/utils_geotiff.py`, `backend/perception.py` | PARTIAL | Implement strict input validation checking CRS compatibility, geographic overlap, band count, modality, and spatial co-registration. Return clear error messages. |
| **12. Downloadable PDF Reports** | ReportLab PDF report generation function present and working. | `backend/audit_trace.py` | PASS | Retain PDF generation and ensure it reflects real confidence metrics, execution traces, and generated visual evidence. |
| **13. Removal of Fake AI Behavior** | Code contains hardcoded text templates, fake IoU strings, hardcoded bounding boxes, fake SAR generation, and synthetic second frames. | Across `backend/models/`, `backend/agent_planner.py`, `eval_benchmarks.py` | FAIL | Eliminate all fake AI behaviors, synthetic input generation, and fixed confidence numbers. Label baseline algorithms as `Classical Baseline`. |
| **14. Portable Deployment & Environment Setup** | `start_server.sh` contains hardcoded user paths (`/home/xetsef/...`). Missing `.env.example` and standard virtualenv launcher. | `start_server.sh`, `backend/models/vqa_caption_tool.py` | FAIL | Remove user-specific paths. Provide `.env.example`, environment specification (`environment.yml`/`requirements.txt`), and portable `start_server.sh`. |
